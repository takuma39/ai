## 追記ルール

新しい MCP を見つけたら、このカタログに追加する。**リンク集ではなく、社内で回るカタログにするための規約。**

### 番号帯

| 帯 | 分類 |
| --- | --- |
| `01`〜`09` | 基礎（導入・最適化） |
| `10`〜`19` | 開発 |
| `20`〜`29` | テスト |
| `30`〜`39` | デザイン |
| `40`〜`49` | 情報・ドキュメント |
| `50`〜`59` | 運用・インフラ |
| `60`〜`69` | データ・AI（予約） |
| `70`〜`79` | 自作 MCP（予約） |
| `90`〜 | 横断（複数 MCP をまたぐテーマ） |

帯の中は**追加順に採番**する。削除した番号は再利用しない（リンク切れを防ぐため）。

### 必須の4節

1. **何ができるか**（できないことも）
2. **設定** — `.mcp.json` または `claude mcp add` の実例。**この節がない記事はマージしない**
3. **実際のプロンプト例** — コピペで使えるもの
4. **使わないほうがいいケース** — `> **こういう場合は入れなくていい**` ブロックで明示

> 2 だけの記事は公式ドキュメントに勝てない。**3 と 4 が記事の価値になる。**

### 執筆時の検証

- パッケージ名は **npm の最終公開日と GitHub の archived バッジ**を確認してから書く
- ツール名は `/mcp` の一覧からコピーする（手打ちの typo は permissions で黙って無視される）
- コマンド・フラグは実際に叩いて確認する。**存在しないフラグを載せると資料全体の信頼を失う**
